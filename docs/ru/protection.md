# Доступ к сайтам

Обычные HTTP-запросы, настроенные зеркала и вход на сайт работают без внешнего сервиса. Необязательный слой доступа
выключен, если `protection` отсутствует. Он не устанавливает браузер, не меняет системный прокси и не скачивает видео.

## Подключение необязательного сервиса

Раздел нужен, если обычные зеркала закрыты браузерной проверкой Cloudflare. Рабочему сайту дополнительное
подключение не требуется. Раскрытая инструкция в настройках объясняет подключение; подсказки у полей отделяют
адрес сервиса, порядок и ограничения восстановления от таймеров раздач. Во встроенной «Инструкции» есть то же
объяснение и разбор ошибок. Верхние разделы настроек остаются закрытыми, пока вы их не откроете.

Если у существующей карточки есть отметка **По требованию**, доверенный модуль уже установлен. Включите
подключение и общий выключатель, затем сохраните; ручной запуск и отдельный автозапуск не нужны. Шаги ниже —
для отдельно запущенного сервиса. Выбор типа в TOW не устанавливает его. Например, `http://127.0.0.1:8191` —
адрес сервиса на компьютере с TOW, а не зеркало сайта или ссылка на раздачу.

1. Отдельно запустите доверенный [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr),
   [Byparr](https://github.com/ThePhaseless/Byparr), [FlareBypasser](https://github.com/yoori/flare-bypasser) или
   [Trawl](https://github.com/germondai/trawl). Не открывайте API в интернет; ограничьте браузеру доступ к LAN,
   link-local и служебным адресам облака. Этот браузер находится вне сетевой изоляции TOW.
2. На компьютере TOW откройте локальный адрес → Настройки → Доступ к сайтам → Добавить подключение. Выберите тип,
   укажите loopback/IP частной сети и порядок. Допускается только путь `/v1`; localhost превращается в 127.0.0.1.
3. Включите подключение и общий выключатель, затем сохраните. Сохранение не обращается к сервису и не подтверждает
   его работу: API проверяется только тогда, когда applying-проверке действительно нужен этот способ. Ответ API не
   доказывает доступ к сайту; его наблюдённое состояние и пауза сервиса показываются отдельно.

После сохранения откройте раздачу с ошибкой на главной и нажмите **Проверить доступ сейчас** либо дождитесь
назначенного повтора. Только новый отказ обычных зеркал с Cloudflare запускает восстановление; рабочее зеркало
не вызывает сервис ради проверки настроек. Состояние API — последнее наблюдённое обращение, не проверка сейчас.
Сброс сохранённого доступа убирает ключи и записи попыток/пауз сервисов, но не пароли сайтов, настройки
подключений или торренты клиента. Он не устанавливает модуль и не отменяет серверное ограничение частоты.

Можно сохранить несколько подключений одного вида. Меньшие номера идут первыми. Отсутствующий модуль, выключенное
подключение, отказ или неудачная попытка не мешают рассмотреть следующее включённое подключение в пределах общего
числа попыток и времени. Успешное прохождение любой защиты не гарантируется.
Если лимит попыток исчерпан без подтверждённого доступа, следующая допустимая проверка продолжит после последнего
использованного подключения: дальние подключения не остаются недостижимыми. Изменение настроек начинает порядок
заново, но не отменяет интервал. Отсутствующие модули и сервисы на паузе API не занимают место попытки.

Для совместимого `/v1`, в том числе отдельно работающего nodriver-форка, выбирайте FlareSolverr; библиотека nodriver
сама по себе не является HTTP-сервисом. FlareBypasser использует `request.get_cookies`, Trawl — `request.get` с
`returnOnlyCookies`. Протоколы проверяются по исходному коду, а не угадываются по названию браузера. TOW не импортирует
и не включает nodriver, zendriver или Camoufox. Фиксируйте и проверяйте версию внешнего сервиса и его зависимостей;
совместимый ответ не доказывает прохождение защиты.

На странице Сайты → дополнительные настройки сайта **Автоматически** разрешает необязательный слой; **Выключено**
запрещает его для этого сайта. **Вход через браузер** выбирает существующий явный вход владельца: внешние сервисы
не подменяют User-Agent этой сессии. Это не скрытый автоматический браузер.

## Порядок проверки

### Установленный Windows-модуль: по требованию

Владелец может установить отдельный модуль FlareSolverr с закрытым манифестом
`runtime/services/flaresolverr/manifest.json` (`tow-local-service/v1`). Это не команда из веб-настроек:
манифест связывает локальный API, фиксированный относительный путь программы, версию, SHA-256 и срок простоя.
Во время проверки TOW ничего не скачивает и не устанавливает. Без модуля сохраняется обычное подключение к API.

Запуск разрешён только при реальном вызове сервиса: настройки, диагностика, предпросмотр, выключенное подключение
и успешные обычные запросы не создают процессов. Отдельный лёгкий контроллер запускает программу по запросу,
последовательно обслуживает браузерные обращения и включает ожидание запуска в общий срок вызова. Если холодный
запуск не успел, текущий запрос завершается вовремя, а свой процесс может прогреться в отдельном пределе двух минут;
следующий запрос использует его без повторного холодного запуска. Контроллер передаёт только
ограниченные запросы cookies публичных проверочных страниц, без данных аккаунта. Токены программы и настройки
прокси не наследуются. Собственное дерево Windows-процессов завершается с контроллером даже при его аварии.
Через пять минут простоя программа останавливается, контроллер завершается. Уже запущенный вручную сервис
используется без принятия под управление и остановки. Автозапуск ОС не требуется.

В настройках установленный модуль отмечен **По требованию**. Отключение подключения запрещает новые запуски;
уже начатый запрос может завершиться, после чего сработает таймер простоя. Повреждённые файлы или манифест
блокируют автоматический запуск. Управление нативным модулем пока поддерживает Windows-комплект; Linux/macOS
сохраняют прежнее независимое подключение к внешнему API. Как и у любого внешнего браузерного сервиса,
его сетевой доступ находится вне ограничений HTTP TOW и должен быть изолирован от частных адресов.

### Последовательность запросов

1. Обычные зеркала, с ранее подтверждённым доступом для точного origin, пока он действителен.
2. Только после отказа обычных зеркал с распознанной проверкой Cloudflare — включённые сервисы по порядку.
3. Сервис получает только проверенную публичную страницу: главную по умолчанию, `/login.php` для Kinozal.
   Не пароль, данные аккаунта, тему, passkey или download. Адрес задаёт доверенный модуль сайта; произвольные адреса
   из настроек и параметры запроса не принимаются.
4. TOW проверяет ограниченный ответ и самостоятельно обращается к этой странице с полученными данными доступа
   и соответствующим User-Agent. Перенаправления ограничены сроком и проверенными публичными путями;
   переход каталога на открытую главную не подтверждает доступ. Запросы темы, скачивания или адреса с параметрами
   по перенаправлению проверочной страницы не выполняются.
5. Нужный ресурс запрашивается обычным защищённым HTTP TOW; при необходимости выполняется обычный вход на сайт.

Каталог Kinozal направляет гостей на `/login.php?m=5`. Доверенная проверочная страница — сам вход, без параметров
запроса и данных аккаунта: это перенаправление больше не мешает подтвердить восстановленный доступ. Доступная
страница входа подтверждает только прохождение браузерной проверки; доступ аккаунта проверяется по нужному
ресурсу отдельно. Проверочная страница входа не может перенаправлять на каталог, главную, адрес с параметрами
или другой origin.

Заголовок [`cf-mitigated: challenge`](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)
однозначно указывает на проверку. Известное название страницы со статусом проверки — запасной признак; обычный
прокси Cloudflare, скрипт или цитата на форуме не являются проверкой. Запрет доступа, ограничение частоты, сбой
сервера, техработы, квота и вход — разные причины, а не повод запускать сервис. Предпросмотр и диагностика его
никогда не вызывают. Перенаправление скачивания к другому origin использует новый клиент без данных входа;
домен cookie из ответа сервиса не разрешает передачу учётных данных другому origin.

Зашифрованный `data/protection.enc` хранит подтверждённый доступ, User-Agent, срок и предварительные записи попыток.
По умолчанию: 30 секунд на цепочку восстановления, до 2 вызовов сервисов, 1800 секунд до новой попытки.
Лимит вызовов общий для всех зеркал и учитывает только действительно начатые обращения к сервисам. Первыми идут
зеркала с наиболее давней попыткой восстановления: дальние зеркала получают шанс и при проверках реже интервала
повтора. Отсутствующий сервис, пауза и нехватка бюджета до вызова не создают новый интервал ожидания.
Успешный анонимный ответ сервиса без ключа доступа разрешает один дополнительный вызов этого подключения после
остальных включённых подключений. Он использует то же резервирование и оставшийся лимит вызовов и времени,
включая запас на независимую проверку; повторное отсутствие ключа не создаёт цикл. Неоднозначные ключи, неверный
ответ, несовпадение области cookie или адреса, пауза API и отказ настоящего ресурса не разрешают такой повтор.
Запись попытки появляется до сетевого запроса, поэтому краш не вызывает запрос каждую секунду. Изменение настроек делает
старый доступ недействительным, но не отменяет паузу. Выключение запрещает его использование в последующих запросах;
уже отправленный запрос отозвать нельзя.

Ошибка соединения и ответы API о занятости/неверном протоколе приостанавливают только этот сервис для всех сайтов:
экспоненциальная пауза начинается с 30 секунд и ограничена 1800; корректный `Retry-After` может увеличить её до суток.
Отказ сайта при повторном запросе, медленная проверка и HTTP 500 не отключают сервис глобально. Переименование или
перестановка подключения не снимает паузу. У записи попытки собственный идентификатор: ответ до сброса или новой
попытки не вернёт старые cookies, не удалит новые и не восстановит старую паузу сервиса. Зашифрованный формат v2
читает v1 без перезаписи при просмотре; обновление происходит при новой записи только этого необязательного кеша.
Ошибки старше суток не увеличивают паузу при первом сбое нового дня. Сервису не отдаётся весь бюджет: до 10 секунд
(треть при меньшем бюджете) остаётся на независимую проверку. Временный сбой связи с проверочной страницей или ошибка сервера
сохраняет проверенный доступ и не служит причиной новой попытки сервиса.
Новая предварительная запись сохраняет ещё действующий доступ при неизменных настройках с его собственным
идентификатором: идентификатор новой попытки не подменяет прежний. После отказа продолжается перебор сервисов;
подтверждённая замена возвращает порядок этого зеркала к началу. Старые данные с идентификатором сохраняются при
записи, без перезаписи при чтении. Прежние версии читателя необязательного кеша безопасно не используют данные с новым
вложенным идентификатором; пароли и состояние торрентов не меняются. Просроченные данные или данные без идентификатора не
переносятся в новую попытку.

Если хранилище не читается, обычный HTTP остаётся доступным, а файл не заменяется молча. На компьютере TOW:
Настройки → Доступ к сайтам → Восстановление → **Сбросить сохранённый доступ**. Старые зашифрованные байты переходят
во временную папку TOW до обычной очистки. Пароли сайтов и настройки сервисов остаются; во время applying-проверки
сброс запрещён. Эта же операция сбрасывает сохранённые паузы сервисов.

Восстановление не повторяет кешированные данные, уже опробованные обычным запросом. Если новая проверка публичной
страницы успешна, но нужный ресурс по-прежнему закрыт проверкой браузера, доступ для origin сохраняется, а отказ
конкретного пути сообщается как ошибка. Повторять решение той же успешной проверки незачем. Отсутствующая
проверочная страница не заменяет исходные причины отказа зеркал.
Если главная или доверенная публичная страница отвергла сохранённую сессию, удаляется только сессия этого запроса.
Обычная проверка главной может использовать cookies аккаунта.
Отказ отдельного пути при рабочей публичной странице, квота, ограничение частоты или сбой её не отменяют.
Предпросмотр не удаляет доступ; запоздалый отказ прежнего запроса не удаляет новую сессию даже с теми же cookies.
Сбой или отказ отдельного пути завершает только попытку этого зеркала; другие допустимые зеркала ещё могут
восстановиться в общем бюджете. Исходные причины сохраняются, пока сам ресурс не даст новый ответ. Ограничение
частоты приостанавливает зеркало однократно; квота или явный запрет доступа прекращают все дальнейшие вызовы
восстановления в этой проверке. Раздача считается удалённой, только если каждое действительно проверенное зеркало
сообщило об удалении, а не когда другое зеркало осталось недоступным.
При разных отказах сохраняются причины каждого зеркала: запрет доступа на одном не означает запрет на всех.

У явного входа через браузер один общий срок, включая подключение и подготовку. У каждой команды также фиксированный
срок ответа: посторонние события браузера не продлевают ни один из них. Отмена закрывает отдельный канал;
ограниченное закрытие соединения (до двух секунд) и обычная очистка процесса/профиля могут завершиться после срока.

## Текущая версия без повторного скачивания

Ограничение частоты сразу приостанавливает запросы к соответствующему зеркалу, включая вход и ручные проверки.
`Retry-After` принимается в секундах или как HTTP-дата, не более суток; без пригодного значения задержка растёт
от 60 секунд до 30 минут. Другие зеркала доступны. Предпросмотр ничего не записывает; поток не спит во время паузы.
Срок серверной паузы хранится отдельно от последнего ответа: успешная другая страница или поздний прежний ответ
не удаляет и не сокращает его. Для отдельного адреса входа срок независимый.

Сайт может иметь `infohash_path` с `{id}`. Для Kinozal preset указывает страницу служебной информации. Принимается
только один явно подписанный текущий инфохеш. Если он совпадает с сохранённой версией, клиент должен независимо
подтвердить принадлежащую TOW задачу, папку и проверенный выбор, прежде чем TOW пропустит скачивание `.torrent`.
Проверка прогресса выполняется. Неизвестный формат или отсутствующая необязательная страница допускают обычное
скачивание; ошибка связи с сайтом сообщается без повторения тех же неудачных запросов. Новое правило, отсутствующая,
чужая или незавершённая задача и новый хеш проходят полный подтверждаемый клиентом путь. Это не обход квоты и не
доказательство актуальности из старого кешированного торрента.

Актуальный путь скачивания Kinozal — `/download.php?id={id}`. Его точный устаревший вариант по умолчанию
`/.dl./download.php?id={id}` читается как актуальный, в том числе в старых импортированных настройках;
чтение не переписывает файл настроек. Собственные пути сохраняются. Старые вставленные ссылки зеркал распознаются.

## Ограничения

Временные сбои сайта получают отдельную ограниченную очередь supervisor: до трёх дополнительных проверок
за непрерывный сбой, с объединением раздач одного сайта. Для обычного транспортного сбоя первая пауза — пять
минут, для Cloudflare — не меньше 30 минут или заданного интервала восстановления. Каждая неудача удваивает
паузу до двух часов; небольшой стабильный разброс до 30 секунд разводит разные сайты. Паузы зеркал сервера
не сокращаются, а обычный HTTP и модули по-прежнему соблюдают собственные защитные сроки. Общий и личный
таймеры не сдвигаются; удалённый владельцем торрент такие проверки не добавляют обратно. После трёх попыток
остаётся обычный график. Пауза, удаление, успех и изменение правил делают прежнюю очередь недействительной.
Резервирование записывается до запуска, поэтому авария не создаёт повтор на каждом тике. Вход, квота, явный
бан, остановленный сайт и законченная одноразовая раздача не попадают в эту очередь.

Главная объединяет временный сбой сайта в одно предупреждение с количеством затронутых раздач; реальные
ответы зеркал остаются в подробностях. Ссылка открывает кнопку «Проверить доступ сейчас». Время повтора
показывается только из совпадающего плана работающего supervisor; просмотр ничего не запускает.
Уведомления объединяются уже для двух раздач, а смена причины между транспортными классами не повторяет
сообщение об одном сбое. Подтверждённое восстановление закрывает ранее сообщённую ошибку один раз.

Отказы доступа сохраняют закрытые безопасные коды причины, этап и длительность: запуск модуля, запрос
к сервису, проверка ответа, публичная страница или настоящий ресурс. Пароли и содержимое ответов не пишутся.
Ответ API всё ещё не является доказательством доступа к сайту.

- `status: ok` сервиса не доказывает успех; доступ подтверждает отдельный запрос TOW.
- Публичная проверочная страница не решает все проверки, включённые лишь для download. Внешний сервис может пробовать
  интерактивную проверку, но TOW не гарантирует её завершение; участие владельца может остаться необходимым.
  Отличающийся IP или отпечаток браузера/TLS может привести к безопасному отказу.
- Cloudflare [Precursor](https://developers.cloudflare.com/cloudflare-challenges/precursor/) может перепроверять
  продолжающийся сеанс и отменять clearance. Работа главной не доказывает доступ к другим страницам или пригодность
  cookies для отдельного HTTP-клиента. TOW проверяет нужный ресурс и записывает отказ повторного запроса; ответ API
  не выдаётся за восстановленный доступ к сайту.
- Сетевые операции и обработка ответа ограничены, но синхронный DNS операционной системы прервать нельзя. Поздний
  ответ не используется; зависший системный resolver может превысить номинальное время.
- HTTP сайта запрашивает только gzip, deflate и identity. Размер сжатых данных, каждого слоя распаковки и результата
  ограничен; повреждённое, незавершённое или неподдерживаемое кодирование отклоняется.
  Пустые ответы, включая перенаправления и HEAD, поддерживаются. Непустой сжатый поток с ошибкой CRC, обрывом или
  лишними данными намеренно отклоняется, даже если более терпимый клиент его принимает.
- Неправильный файл настроек остаётся ошибкой конфигурации. Недоступный настроенный сервис не запрещает обычную
  работу с сайтами. Импортируемое расширение — доверенный код, а не изолированная песочница.
- Последний ответ зеркала не доказывает работу всех его адресов: главная может работать, а скачивание — нет.
  Смотрите фактическую ошибку раздачи.
