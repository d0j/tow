## 2. README

### Шапка — всегда одинаковая, по центру

```html
<div align="center">

# TOW

**Torrent topic watcher.** Follows tracker topics that replace their `.torrent` in place and adds every new
revision to your torrent client.

[![CI](…/ci.yml/badge.svg)](…) [![Release](…)](…) [![License: MIT](…)](LICENSE) [![Python 3.14](…)](…) [![Platforms](…)](#install)

**English** · [Русский](README.ru.md)

[Install](#install) · [Usage](#usage) · [Remote access](#remote-access) · [Docs](#documentation) · [Changelog](CHANGELOG.md)

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/images/home-en-dark.png">
  <img alt="…" src="docs/images/home-en-light.png" width="900">
</picture>

</div>
```

- **Название** — `# TOW`, без эмодзи и слоганов.
- **Описание** — одна фраза: что делает программа. Жирным только определение («Torrent topic watcher.»).
- **Бейджи** — в этом порядке и не больше пяти: CI, Release, License, Python, Platforms. Без «звёзд», «скачиваний»
  и «PRs welcome».
- **Переключатель языка** — `**English** · [Русский](README.ru.md)`; в русском — наоборот. Текущий язык жирным,
  без ссылки.
- **Навигация** — ссылки на разделы через ` · `, не больше шести.
- **Скриншот** — пара тёмный/светлый через `<picture>`, GitHub сам выбирает по теме читателя.

### Порядок разделов

1. Features / Возможности — 6–8 пунктов, каждый начинается с **жирного слова**, одна-две строки.
2. Supported / Что поддерживается — таблица из двух колонок.
3. Install / Установка — по одному блоку на систему (см. ниже).
4. Usage / Работа — первые шаги нумерованным списком, затем таблица команд.
5. Remote access, Update and backups — таблицы.
6. Documentation / Документация — таблица ссылок.
7. License / Лицензия — одна строка лицензии и короткий отказ от ответственности.

### Чего в README нет

- «Кому подойдёт», «чем не является», история проекта, благодарности, планы — это в `docs/`.
- Абзацев длиннее трёх строк. Если нужно больше — это отдельный документ.
- Повторов: одно и то же объясняется в одном месте, остальные ссылаются.

### Установка — по образцу Ollama

Один блок на систему, в каждом — самый простой способ и одна альтернатива:

| Система | Основной способ | Альтернатива |
|---|---|---|
| Windows | скачать `TOW-windows-x64.zip`, распаковать, дважды щёлкнуть `Start TOW.cmd` | `irm …/install.ps1 \| iex` |
| macOS | `curl -LsSf …/install.sh \| sh`, затем `Start TOW.command` | — |
| Linux | та же команда, затем `~/TOW/start-tow` | `--autostart`, `--desktop` |

- Ссылки на файлы — только через `https://github.com/d0j/tow/releases/latest/download/<файл>`, чтобы не устаревали.
- Ручная установка (git) — не в README, а в `docs/install.md`.
- Сразу после установки — блок `> [!IMPORTANT]` про копию `keys/master.key`.

### Оформление

- Команды — в блоках кода с языком (` ```powershell `, ` ```sh `); одна команда — одна строка.
- Списки команд и вариантов — таблицами, а не абзацами.
- Выноски GitHub: `> [!IMPORTANT]` — то, без чего пользователь потеряет данные; `> [!WARNING]` — опасные действия;
  `> [!NOTE]` — по необходимости. Не больше двух выносок на README.
- Строки не длиннее 120 символов (кроме таблиц и ссылок).
- Все ссылки и якоря проверяет `tests/test_docs_links.py`; сломанная ссылка — сломанный gate.

### Скриншоты

- Только **вымышленные данные**: выдуманные названия («Northern Lights · season 2», «Часовая гавань»), пути вида
  `D:/TV/…`, номера тем вида `1234567`. Никогда — снимок настоящей установки.
- Ширина окна 1200 px, масштаб 2, кадр обрезан по содержимому, без пустого места.
- Четыре файла: `home-<en|ru>-<dark|light>.png`. Русский README показывает русский интерфейс.
- Пересъёмка — скриптом по временной установке на свободном порту; живой TOW не трогаем.

## 3. Языки и слова

- **Английский — основной** для кода, коммитов, `docs/`, README.md, CHANGELOG.md.
- **Русский — отдельными файлами** с той же структурой: `README.ru.md`, `CHANGELOG.ru.md`, `docs/ru/…`. Пишем
  по-русски, а не подстрочником; обращение на «вы».
- Один термин — одно слово:

| Понятие | English | Русский |
|---|---|---|
| то, за чем следит TOW | topic | раздача |
| трекер с адресами | site | сайт |
| адрес сайта | mirror | зеркало |
| qBittorrent и др. | torrent client | торрент-клиент |
| новая версия .torrent в теме | revision | новая версия |
| Telegram и др. | messenger | мессенджер |
| ключ шифрования | master key (`keys/master.key`) | мастер-ключ |

- Названия программ — как у авторов: qBittorrent, Transmission, Deluge, Telegram, ntfy, macOS, Windows.
- Без англицизмов в русском: не «секреты», «сессия», «ридбэк», «редирект», а «пароли и токены», «вход»,
  «проверка», «перенаправление».

## 4. Документация

| Документ | Для кого | Что внутри |
|---|---|---|
| `docs/install.md` (+ `docs/ru/`) | новичок | установка по шагам, что будет на экране, удаление, «если что-то не так» |
| `docs/guide.md` (+ `docs/ru/`) | пользователь | экраны, цвета, уведомления, копии, решение проблем |
| `docs/PORTABLE.md` | администратор | устройство папки, `tow run`, автозапуск, обновления |
| `docs/architecture.md` | разработчик | процессы, модули, данные, безопасность |
| `docs/EXTENDING.md` | разработчик | как добавить клиент, мессенджер, сайт, язык, страницу |
| `docs/ROADMAP.md` | все | что сделано, что дальше, чего не будет |

- Каждый документ начинается с одной фразы «для чего он» и содержания, если длиннее экрана.
- Инструкции для новичков — пошагово, нумерованным списком; каждый шаг — одно действие и что пользователь увидит.

## 5. Коммиты

```text
<Область>: <что изменилось, повелительно, по-английски, до 72 символов>

<Зачем — 1–5 строк: причина, что было не так, как проверено.
Перенос строк на 72 символах.>

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

- **Одно логическое изменение — один коммит**, вместе с тестом.
- Тема — что сделано, тело — почему. Без «fix stuff», «update», «WIP».
- Область — модуль или тема: `web:`, `installers:`, `README:`, `ci:`, `release:`.
- Коммит выпуска: `release: vX.Y.Z - <главное одной фразой>`.
- Подпись `Co-Authored-By` — только для коммитов, написанных агентом. Имена моделей в коммитах не пишем.
- Хуки: перед коммитом — быстрый gate, перед push — полный. Не обходим (`--no-verify` запрещён).

## 6. Ветки и защита

- **`main`** — единственная постоянная ветка, всегда рабочая. Защищена правилом «Protect main»:
  - нельзя удалить ветку и переписать историю (force push);
  - слияние — только после зелёного CI на Windows, Ubuntu и macOS;
  - обходить правило может только владелец (`d0j`) — для коммитов выпуска.
- Чужие изменения и обновления Dependabot — только через Pull Request.
- Временные ветки агентов и экспериментов в публичный репозиторий не пушим.
- Историю, уже отправленную в `main`, не переписываем никогда.

## 7. Версии и теги

- **Семантические версии** `MAJOR.MINOR.PATCH`:
  - PATCH — только исправления;
  - MINOR — новые возможности без поломки старых;
  - MAJOR — когда старая установка не обновится без действий пользователя.
- Тег — **аннотированный** `vX.Y.Z` (`git tag -a v1.22.2 -m "TOW 1.22.2"`), версия совпадает с `pyproject.toml`.
- Отправленный тег **не двигаем и не удаляем**. Если выпуск по тегу не прошёл проверку — выпускаем следующий
  PATCH и пишем об этом в CHANGELOG одной фразой.
- Перед тегом: версия в `pyproject.toml`, `uv lock`, разделы CHANGELOG на двух языках, полный gate на чистой копии.

## 8. CHANGELOG

Формат [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), два файла с одинаковыми версиями:

```markdown
## [1.22.2] — 2026-10-02

### Added      (Добавлено)
### Changed    (Изменено)
### Fixed      (Исправлено)
### Removed    (Удалено)
### Security   (Безопасность)
```

- Новые записи — сначала в `## [Unreleased]` / `## [Не выпущено]`, при выпуске раздел получает номер и дату.
- Пишем для пользователя: что он заметит, а не какой файл поменялся. Имена команд и файлов — в `обратных
  кавычках`.
- Одна запись — один пункт, одна-три строки. Пустые разделы не оставляем.

## 9. Выпуски на GitHub

Выпуск собирает и публикует `.github/workflows/release.yml` по тегу. Руками выпуски не создаём.

### Файлы выпуска

Имена постоянные — на них ведут ссылки `releases/latest/download/…`. У каждого файла есть подпись (label),
которую GitHub показывает вместо имени, по шаблону `<Для кого>: <файл> - <что сделать>`:

| Файл | Подпись |
|---|---|
| `TOW-windows-x64.zip` | Windows: TOW-windows-x64.zip - extract, double-click Start TOW.cmd |
| `install.ps1` | Windows installer: install.ps1 - run it with the PowerShell line in the notes |
| `install.sh` | Linux and macOS installer: install.sh - run it with the curl line in the notes |
| `tow-source.tar.gz` | Source archive: tow-source.tar.gz - used by install.sh and updates |
| `SHA256SUMS` | Checksums: SHA256SUMS - SHA-256 of the files above |

### Описание выпуска

Генерирует `scripts/release-notes.py`, порядок всегда такой:

1. `## Download` — таблица «система → что сделать», затем одна фраза о служебных файлах (install.ps1/.sh,
   tow-source.tar.gz, SHA256SUMS, Source code), ссылка на инструкцию и напоминание о копии ключа.
2. `## What's new` — раздел версии из `CHANGELOG.md`.
3. Под спойлером `<details><summary><b>По-русски</b></summary>` — то же по-русски из `CHANGELOG.ru.md`.

- Заголовок выпуска — `TOW X.Y.Z`; для первого выпуска линии можно `TOW X.Y.Z — <главное>`.
- Выпуск не публикуется, пока не прошли все проверки: сборка, запуск архива, установщики на трёх системах.

## 10. CI

- Действия закреплены **полным хешем коммита** с версией в комментарии:
  `uses: actions/checkout@3d3c42e… # v7.0.1`. Обновления предлагает Dependabot.
- Права — `contents: read`; `contents: write` — только у задания, которое загружает файлы выпуска.
- Имена обязательных проверок не переименовываем — на них ссылается защита ветки:
  `gate (windows-latest)`, `gate (ubuntu-latest)`, `gate (macos-latest)`.
- Предупреждения GitHub (устаревший Node, устаревшие runner'ы) убираем сразу, не копим.

## 11. Чистота данных

В репозиторий и в историю не попадают:

- пароли, токены, cookies, ключи, `master.key`, файлы из `data/`;
- имена компьютеров, адреса домашней сети и Tailscale, пути к личным папкам (`C:\Users\<имя>`, `D:\<личное>`);
- настоящие названия раздач, номера тем, логины на сайтах;
- упоминания других личных проектов.

В тестах и примерах — только вымышленное: `Show A` / «Сериал А», `1234567`, `192.168.1.x`, `100.64.1.1`,
`C:\Users\user`, `D:\TV`. Перед публикацией — `scripts/history-scan.py` и поиск по этим признакам.

## 12. Проверка перед выпуском

- [ ] Полный gate зелёный (`pwsh scripts/gate.ps1`), и на чистой копии тоже.
- [ ] Версия в `pyproject.toml` = тег; `uv lock` обновлён.
- [ ] Разделы `CHANGELOG.md` и `CHANGELOG.ru.md` для версии заполнены и совпадают по смыслу.
- [ ] README и документы обновлены, если поменялось то, что видит пользователь; ссылки проверены тестом.
- [ ] Нет личных данных (раздел 11).
- [ ] Тег аннотированный, отправлен; workflow выпуска прошёл целиком; файлы с подписями на месте.
- [ ] Проверено руками как пользователь: скачать по ссылке `latest`, установить во временную папку на свободном
      порту, запустить, остановить, удалить. Рабочая установка не задета.
