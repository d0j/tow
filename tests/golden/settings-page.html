      Settings

      Site access Off

      Use this section when a site shows a Cloudflare browser challenge instead of a topic. If topics check without errors, you do not need to connect anything.

      How it works and how to connect

      TOW tries ordinary mirrors first. If a Cloudflare challenge blocks access, an enabled service opens an anonymous public page in its browser. TOW receives clearance and checks the actual topic itself; a service response alone is not success.

      1. An On demand card means the module is already installed: no manual start is needed. For another connection, install and run your chosen service separately. TOW does not install services for you.
      2. Choose the running service's type and enter its address, not a site or topic address. For example, http://127.0.0.1:8191 is a service on the TOW computer. Another computer needs its private-network IP; never expose the API to the internet.
      3. Select Use this connection and the overall Use optional challenge recovery switch, then Save. On Sites, the site must allow these services; Off for this site takes precedence.
      4. Open the failed topic on Home and select Check access now, or wait for its scheduled retry. TOW contacts a service only if ordinary mirrors encounter Cloudflare again. Saving settings does not test it.

      Read more in the guide

      Site access

      Overall switch for additional services. Ordinary mirrors and browser sign-in also work without them. The change applies when saved.

      Add a connection

      Choose the program serving this address. Selecting a type does not install it.

      The service address TOW uses, not a site mirror. 127.0.0.1 means the TOW computer; /v1 may be omitted.

      1 is first, 2 is next. Each number must be unique.

      If the first method fails, TOW considers the next within the shared call and time limit. Once that limit is reached, the next eligible check continues with later connections. Disabled connections and services in cooldown are not called.

      Connection status is the last observed response, not a test now. API answered does not prove topic access. Opening settings never starts a module; the topic on Home shows the last check result.

      Attempt limits

      One deadline for all service calls and independent access verification: 5–90 seconds. Not a timeout for each topic.

      Minimum pause before another recovery attempt for one site origin: 60–86400 seconds. 1800 s = 30 minutes. Not the global or personal topic timer; the error shows a scheduled retry when known.

      1 to 4 service calls in one recovery chain, shared across mirrors. A missing-clearance retry also consumes this limit. Not the number of topics checked.

      Save applies switches, addresses, order and limits. It does not start a service or download a .torrent.

      If access is still blocked

      Expand the topic's warning for each mirror's reason and retry time. The log identifies the failed stage: module startup, service response or topic access. A connection failure needs its type and address checked; a sign-in error needs the account checked on Sites.

      Services do not remove bans, download quotas or request rate limits. Wait out a 429 pause. An interactive check may require supported browser sign-in; access through every future challenge is not guaranteed.

      Use only services you trust and sandbox their browser's network access. They receive an audited public page, not your password, sign-in cookies or topic link. TOW keeps only verified clearance, encrypted and time-limited. Interactive challenges may still require your action; download limits remain enforced.

      Reset saved access

      Use only for damaged saved data or a stale clearance problem. Removes Cloudflare clearance, retry reservations and service cooldowns; site passwords, connections and torrents remain. Reset does not install a module or cancel site limits. The old encrypted record stays in the temporary folder until cleanup; a running check blocks reset.

      Release notes

      More: history, rollback and log

      Install another version or roll back

      Web updates support published stable versions from 1.22.21. Data is kept; an incompatible data schema refuses the change. Older releases require the terminal and may not understand current data.

      Stable releases only. Nothing is installed without you.

      How to update

      The “Update” button above installs a newer release, or “Update TOW” in the TOW folder on the computer running TOW (“Update TOW.cmd” on Windows, “Update TOW.command” on macOS, update-tow on Linux). For a chosen version, open a terminal in the TOW folder (the one with config.yaml) and run the command below with that version: it shows how. The update makes an update snapshot first.

      scripts/tow update --ref v

      Nightly backups

      Settings, history and encrypted passwords. Automatic copies follow the night schedule and catch up after the computer turns on. Retention is set below.

      Older nightly backups are removed only after a new copy passes verification. The new copy, the three newest earlier copies (whatever their age) and copies with future dates are kept. Default: 7 days. Free space for a complete copy and a reserve is checked before writing.

      Folder for nightly backups
