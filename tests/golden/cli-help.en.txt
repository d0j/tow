$ tow --help
usage: tow [-h] <command> ...

TOW watches topics on torrent sites and hands new versions to your torrent client.

positional arguments:
  <command>
    version           show the TOW version
    status            one line on TOW: running or not, torrent client, sites, topics, last and
                      next check, autostart
    doctor            ask the torrent client and the sites now and report what answers
    permissions       who can get into TOW's folders; fix closes them
    adopt             adopt topics whose torrent is in the client without the label tow: TOW marks
                      it (nothing else changes) and manages it from then on
    check             check the topics now (a preview that changes nothing unless --apply)
    access            network access from other devices: on, off or status
    secrets           the encrypted store of passwords and tokens
    keys              the master key inside the install (keys/master.key)
    export            save the settings, topics, history, passwords and tokens into one file
                      protected by a passphrase (for another install, even with another master
                      key)
    import            restore from a `tow export` file (a preview unless --apply)
    import-rollback   put back what an import replaced, from its checkpoint
    backup            make a nightly backup now (into backup_dir)
    restore-snapshot  restore the data from a nightly backup
    watchdog          one watchdog pass now, as tow run makes every 10 minutes: is TOW up and are
                      the checks running? Its alerts go to the messengers too; it restarts nothing
    password          set a new TOW password and reminder (the old one is not needed)
    run               run TOW as one supervised service: web page, schedule, nightly backups and
                      watchdog
    start             start TOW in the background (unless it runs) and open its page in the
                      browser
    stop              stop the running `tow run` (it lets a running check finish)
    restart           restart the web server of the running `tow run`
    setup             rebuild the environment: a command of the launcher, not of this environment
    autostart         start TOW with the computer (Task Scheduler, systemd, launchd)
    update            how to update this install to a release

options:
  -h, --help          show this help message and exit

exit codes (every command):
  0    done
  1    a wrong command or option
  2    done in part: a topic, a mirror or a step failed
  3    cannot run: config, passwords and tokens, the lock or a file is missing or broken
  130  interrupted (Ctrl+C)

“setup” is a command of the launcher (scripts\tow.cmd setup): it rebuilds the environment after a
move or an update, with TOW stopped.
Every command explains itself: tow COMMAND --help

$ tow permissions --help
usage: tow permissions [-h] [--owner ACCOUNT] [--json] [{status,fix}]

Shows whether other accounts of this computer can get into the TOW folder, the key folder and the
data folder, and who owns them. “fix” closes them; a folder another account owns (one created from
an administrator terminal) is given to its owner when run in a terminal opened with “Run as
administrator” (Linux, macOS: with sudo): the account named with --owner, else the one that
already owns the TOW folder, else the one TOW's autostart runs as, else the one that opened the
terminal. Nothing outside the TOW folder changes.

positional arguments:
  {status,fix}     status (default) or fix

options:
  -h, --help       show this help message and exit
  --owner ACCOUNT  with fix: the account to give the folders to (COMPUTER\name or name), when TOW
                   cannot tell whose install it is
  --json           machine-readable output (JSON), also when the command fails

$ tow keys --help

copy away from this computer. status: which key file is in use (never the key itself); adopt: copy

$ tow backup --help
usage: tow backup [-h] [--json]

Makes a nightly backup now, as “Back up now” in Settings → Backups does: a signed copy of the
settings, topics, history and encrypted passwords and tokens in backup_dir (default backup/night).
The master key is never in it. Older copies are removed by the retention setting only after the
new copy is checked.

options:
  -h, --help  show this help message and exit
  --json      machine-readable output (JSON), also when the command fails

$ tow restore-snapshot --help
usage: tow restore-snapshot [-h] --path PATH [--apply] [--json]

Restores the data from a nightly backup (its folder in backup_dir), also while TOW runs. Without
--apply it only checks the copy (that needs this install's master key) and shows what would
change. With --apply it first keeps the current data in data/before-restore-* and puts it back by
itself if anything fails. Network access stays as it is, and History keeps what happened after the
copy.

options:
  -h, --help   show this help message and exit
  --path PATH  the nightly backup's folder
  --apply      restore (without it: check and preview only)
  --json       machine-readable output (JSON), also when the command fails

$ tow update --help
usage: tow update [-h] --ref REF

An update replaces this very environment, so it does not run from here: this command prints what
runs it (the install's base Python with app/scripts/update.py, deploy.ps1 in a git clone on
Windows, or the update file in the TOW folder for an install without git). The update stops TOW,
keeps a snapshot of data/ and config.yaml, installs the release, starts TOW and goes back by
itself if anything fails.

options:
  -h, --help  show this help message and exit
  --ref REF   the release tag, for example v1.22.0; an install without git also takes latest
